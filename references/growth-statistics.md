# 增长统计：可计算量、缺失数据与待验证规律

本说明用于读取 **X 单帖 analytics 与真实粉丝快照**，不把公开热度包装成涨粉机制。执行与字段规范见 [测量规范](measurement.md)，代码事实与操作假设见 [算法行动指南](algorithm-field-guide.md)。X 的推荐权重乘预测概率或连续预测值，不能把自己的操作次数代入排名公式。

## 先区分现在能算什么

所有时长以小时计算；每个数保留自己的采集时间、来源页面、帖子身份与版本。`null` 表示证据不足，0 只用于确实读到零。

| 指标 | 定义与分母 | 当前状态 / 需要补充 |
| --- | --- | --- |
| 粉丝存量 `F(t)` | 某次主页显示的总粉丝数 | 已有观察；不是窗口内关注事件数。首次 175 缺准确时间，不计算其速度。 |
| 平均净速度 `v` | `ΔF / Δt`，人/小时 | 带时间的相邻观察可算；新增与流失未分离，窗口内加入又离开的人也可能不可见。 |
| 净速度斜率 `a` | 两个平均速度之差 / 两窗口中点的时间差，人/小时² | 至少三个有效时间点可作描述；窗口很不等长时须展示时长，不能当作瞬时加速度或策略效果。 |
| 相对净增长率 | `ΔF / (F_start × Δt)`，每小时 | 起点大于零且时间准确时可算；不是未来指数增长率，不外推“指数爆炸”。 |
| 蓝 V 存量 `B(t)` / 新增蓝 V `N` | 存量为同次名单内已确认 blue；新增为完整全粉丝、稳定 ID 差集内 after 为 blue 的身份 | 认证名单数量不等于蓝 V 存量；认证升级不等于新增。本轮确证新增仍不足，不能由总粉丝净增推算。 |
| 展示事件速度 / 斜率 | 同帖、同版本、同界面的 `Δimpressions / Δt`；斜率也按窗口中点算 | 有前后计数才能算。公开 views 与 owner impressions 分别记录；计数下降先核对，增量置 null。 |
| 互动事件比 | 同帖同时间段 `engagement_events / impression_events` | 可从匹配的 analytics 算；可含多次动作与重复展示，不是用户互动概率，也不是去重触达。 |
| 详情 / 主页访问 / 链接点击事件比 | 三项分别除以该帖同段展示事件数 | 分开算，缺任一分子/分母或分母为零则 null；不是严格嵌套漏斗。 |
| 单帖带来的关注转化 | 有效归因的关注事件 / 明确定义的同段曝光或访问分母 | 缺少归因就 null。账号同期涨粉不能填成这条帖子的转化。 |
| 24 / 72 小时队列留存 | 初始队列稳定 ID 中仍在完整粉丝名单的比例 | 须补后续完整快照；未完成窗口不能填结果，handle 改名也不能直接判流失。 |
| 新增高质效率 / 投入回报 | 确证新增高质蓝 V `H / Δt`；另列 `H / active_work_hours` | 缺完整新增身份、判定或实际工作时间就 null；观测时长不等于投入工时，没有收入/成本就不算财务 ROI。 |

当前 `2/5=40%` 描述已审核的五个**新观察到的蓝 V 身份**。它不是代表性抽样，也不是已确认新增的完整总体；不能配一个人口置信区间，或说下一位粉丝有 40% 概率高质。另一个不完整名单中的 `2/2` 不得拼进这五人分母。

## 非等间隔的速度与加速度

对真实观察 `t_i, F_i`，令 `d_i = t_i - t_(i-1)`：

```text
v_i = (F_i - F_(i-1)) / d_i
m_i = (t_i + t_(i-1)) / 2
a_i = (v_i - v_(i-1)) / (m_i - m_(i-1))
    = 2 × (v_i - v_(i-1)) / (d_i + d_(i-1))
```

`a_i` 是两段平均净速度的斜率。不要用本次刷新间隔代替中点间距，不把 5 分钟零变化与下一段 70 分钟增加解读为瞬时跃升。若前段速度为零，其百分比增幅为 null；重复时间、缺时间、缓存未推进或窗口重叠须先处理。图表展示观察点与区间长度，连线只作阅读辅助，不补造中途轨迹。

若确实掌握整段关注与取关事件，才可写 `ΔF = G - L`、`v = G/Δt - L/Δt`。仅有端点快照差集时，只是加入后仍在名单与离开后仍不在名单的净账目，不能声称掌握所有瞬时事件。速度、加速度只是数学差分名称，不是物理机制定律。

## 单帖 analytics 优先，别造漏斗概率

对帖子 `j` 和实际窗口 `[t0,t1]`，分别计算 `ΔI_j`（展示）、`ΔE_j`（互动）、`ΔD_j`（详情）、`ΔP_j`（主页访问）、`ΔC_j`（链接点击）。两次记录须来自同一指标定义、同一帖版本与统计页面；首次观察没有前值，不能悄悄补零。窗口要按实际采集时间记录，并注明距首次发布的真实帖龄及迟到量。

- `ΔE_j / ΔI_j` 是互动事件/展示事件比；同一人可重复展示或执行多种动作，数值可大于 1，不能解释为超过 100% 的用户概率。
- `ΔD_j/ΔI_j`、`ΔP_j/ΔI_j`、`ΔC_j/ΔI_j` 单独显示。不要假设点击者必经详情、主页，也不要相乘得到关注概率。
- 累积计数比与区间增量比各有用途，必须标明口径，不混用。不同帖子展示事件相加只能叫事件总量，不能叫人数；编辑版本与同一会话也不能拼成去重受众。
- `1000 × ΔF / ΣΔI` 最多是对齐窗口里的“每千次展示同期净粉丝变化”，可为负，不能叫单帖关注转化率。未覆盖其他帖、搜索、主页或并行运营时，连这个描述性比也应保留覆盖缺口。

账号自身点赞、回复、打开页面等单列操作日志。无法从总数剔除时，独立受众计数为 unknown，不猜一个扣除值；不可见的不感兴趣、静音、屏蔽、举报也保持 unknown。不得为提高任何比值诱导重复刷互动。

## 质量、粉丝/关注比例与留存

沿用 `public-v1` 三个内容门槛：主题相关、原创、实质信息；阅读至少三条近期原创并保留公开证据，三项均满足才标 high，证据不足标 unknown。蓝 V 是范围条件。不要因为比例好看改写历史判定或降低内容门槛。

同次主页读到粉丝 `f` 与关注 `g` 时，另列网络信号 `s = ln((f+1)/(g+1))`，这里 `ln` 是自然对数，`+1` 仅为零值平滑。它便于比较数量尺度，**不是高质量阈值、真伪鉴定或互关率**；没有计数/时间就 null。原始 `f/g` 在 `g=0` 时未定义，不能把平滑信号伪装成原始比。该信号先用于安排人工审查顺序；其是否提升高质发现率须在后续有标签样本上验证，不能用当前少量成功案例临时挑阈值。

区分两种分母：

- **新蓝 V 质量占比**：`H_new / N_new`。未知质量 `U` 留在 `N_new` 中，分类边界为 `[H_new/N_new, (H_new+U)/N_new]`，不是置信区间。`N_new=0` 则未定义；部分或认证名单只报捕获队列的边界，全窗口为 null。
- **存量质量密度**：同次完整全粉丝名单中已判高质的蓝 V `H_stock / F_stock`。如已识别全部徽章但蓝 V 质量有未知，可显示 `[H_stock/F_stock, (H_stock+U_blue)/F_stock]`。只审核了新增者时不能用其 H 除以全账号存量冒充此密度；未完整覆盖则总体密度 null。

对冻结的初始蓝 V 队列及其中高质子队列，分别测 24/72 小时的身份留存、blue 标记留存；二者不是一回事。留存分母固定为初始合资格稳定 ID，不因后续流失或质量重判缩小。保存后续实际快照时间；若只知道首次观察时间而非真实关注时间，就称“首次观察后留存”。分母为零、名单不完整、身份不稳定或到期未采集时，完整留存率为 null。

## 怎样检验曝光和涨粉规律

先做预注册的单变量帖子实验：写下主要指标（优先确证新增高质蓝 V/小时；单帖层面先用 analytics）、最小实际价值差 `δ`、判定规则、固定窗口及停止条件，再安排发布。按主题/形式/帖龄、时段与日期组成可比块，在块内随机分配本轮唯一改变的变量与发布顺序；记录并行内容、广告、关注动作和观众规模。控制可控制的干扰因素，剩余因素尽量随机化，是 [NIST 随机分块设计](https://www.itl.nist.gov/div898/handbook/pri/section3/pri332.htm) 的原则；这里的具体 X 实验方案是本技能提出的待验证设计。

固定发布后 60 分钟、24 小时、72 小时观察，实际采集早/晚都记原时刻，不冒充到点结果。重复刷新不是新实验单位；同一帖多次计数、同一作者多次回复、重叠窗口不能当作独立样本。分析不确定性时，按帖子或日期等真实分配/依赖单位分块重采样（bootstrap），不是按每次页面刷新重采样；块太少就只做描述。

没有通用“30 人即显著”阈值。先用 pilot 估计波动、聚集/重复性及可用观察成本，在 δ 和所需功效下确定帖子/日期块数量，预先固定后再收正式数据；缺足够信息就不报功效或有效置信区间。完整队列的 H/N 是该队列的已观察构成，Wilson 等二项区间另需清楚的代表性与独立抽样前提；当前 2/5 不满足这类总体推断前提。多次试到一个好看的结果再停止，也不能当作预定检验胜出。

在有充分跨日数据、非负确证新增事件和可靠展示窗口后，可比较一个**候选**负二项模型：`Y_t ~ NB(μ_t, k)`，`log μ_t = log(exposure_t) + 内容/时段/日期等协变量 + 预注册的滞后项`，其中 exposure 必须大于零。负二项拟合与公式内 offset 的实现支持可见 [MASS 官方 glm.nb 文档](https://stat.ethz.ch/R-manual/R-devel/library/MASS/html/glm.nb.html)；其适合本账号与曝光弹性固定为 1 的 offset 假设，均须另行检验。

`Y_t` 只能选定义一致的新增计数，不能把可能为负的净粉丝变化塞进 Poisson/负二项。若有 G/L，分别考虑新增与流失模型；如果只有净变化，就保持描述性分析。曝光、发布时间和涨粉可能共同受内容质量/其他运营影响，滞后相关也不是因果；模型尚未拟合、验证或控制混杂时，参数、未来成功概率和指数增长预测全部留空。
